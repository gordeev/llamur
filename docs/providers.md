# Внешние модели по API

В 0.6.1-dev исходящий клиент поддерживает текст и явные вложения: OpenRouter, OpenAI Chat
Completions, OpenAI Responses, Anthropic Messages (Claude) и серверы с совместимым
протоколом. Это отдельный источник ответа. Локальный GGUF и локальный сервер
llamur работают по прежнему; ошибки не переключают диалог в облако.

## Подключение

1. Откройте нижнюю вкладку Настройки → Подключения по API → Добавить подключение.
2. Выберите пресет или свой сервер. Укажите API key и model ID либо запросите
   каталог. Для нестандартного API выберите протокол и полный base URL без
   конечного `/chat/completions`, `/responses` или `/messages`.
3. Активируйте нужные модели. Можно подключить несколько провайдеров и моделей;
   список «Активные модели» позволяет скрыть ненужные.
4. Нажмите синий + на главном экране. Выберите активную модель, временный или
   постоянный диалог и папку; новый диалог пустой. Затем напишите сообщение. Enter/стрелка отправляют,
   Shift+Enter переносит строку; квадрат останавливает запрос.

| Пресет | Base URL | Протокол |
| --- | --- | --- |
| OpenRouter | `https://openrouter.ai/api/v1` | Chat Completions |
| OpenAI | `https://api.openai.com/v1` | Responses или Chat Completions |
| Anthropic | `https://api.anthropic.com/v1` | Messages |
| Свой сервер | HTTPS или явно подтверждённый HTTP URL | Выбранный совместимый протокол |

Лимит ответа задаётся отдельно в подключении (по умолчанию2048, до131072).
Это запрошенный бюджет, включая reasoning, а не обещание такого ответа: реальные
лимиты модели/контекста задаёт провайдер. Параметры thinking/reasoning/temperature
можно явно задать JSON-полем; неподдержанный параметр даёт ошибку. Пустой JSON
оставляет defaults провайдера. Для native OpenAI Chat выбран
`max_completion_tokens`, для обычного совместимого Chat — `max_tokens`.
Точный usage берётся из ответа провайдера; локальный tokenizer не применяется.
Ползунок контекста относится к GGUF на телефоне, а не к удалённой модели.

Управление подключениями, каталог, локальные модели, профили, Hugging Face и
менеджер места открываются полноэкранными страницами с кнопкой «Назад».
Переключатель локального thinking меняет настройку на месте. Для OpenRouter в
подключении есть «Как у провайдера / Включено / Выключено»; обязательный reasoning
модели нельзя отключить. Для других API остаются явные параметры JSON.

## Сжатие контекста (локально и по API)

Меню диалога → **Контекст и сжатие** → **Сжать контекст** создаёт сводку той же
моделью. После завершения над чатом появится кнопка просмотра: сводку можно
прочитать, применить или не применять. Активную сводку можно посмотреть и отменить.
Сжатие меняет только рабочий ввод модели; список исходных сообщений и вложения
не удаляются. Постоянный чат сохраняет оригинал и сводку в зашифрованном хранилище
по своему сроку, временный — только в RAM. Пределы хранения продолжают действовать;
компакт не превращает архив в неограниченный.

**Настройки → Диалоги → Автоматически сжимать контекст**: по умолчанию выключено.
Если включить, перед отправкой при заполнении около80% окна с учётом резерва ответа
сначала создаётся и применяется сводка, затем отправляется исходный вопрос ровно
один раз. По возможности сохраняются1–2последних полных хода без пересказа.
Длинный старый префикс обрабатывается частями, максимум16запросов на одно сжатие.
Для API это дополнительные запросы по тарифу выбранного провайдера; модель и
endpoint не подменяются, оплачиваемые ошибки автоматически не повторяются.
Локальные веса, квантизация и арифметика инференса не меняются.

Для GGUF заполнение проверяется точным tokenizer загруженной модели. Для API
используются сообщённый usage и консервативная оценка текста; это не точный
tokenizer API, а изображения/PDF могут занимать больше. Окно берётся из каталога
или задаётся в странице сжатия диалога (0возвращает каталог). Без известного окна
автокомпакт не включается для этого диалога; ручное сжатие просит указать окно.
Это не меняет реального ограничения на сервере.

Сводка — **пересказ с потерями**: полнота зависит от модели, сохранность всех
деталей не гарантируется. Скрытое reasoning не пересказывается; его служебные
подписи/opaque payload не переносятся через границу нового контекста. Следующие
ответы получают сводку и недавние сообщения. При отмене исходный ввод возвращается
вместе с сообщениями, появившимися после сжатия; он снова может превышать окно.
Автокомпакт после отмены или своей ошибки приостанавливается для чата; есть кнопка
«Возобновить автокомпакт». Незавершённая, пустая, не уменьшающая ввод или всё ещё
не помещающаяся автоматическая сводка отклоняется. Черновик не отправляется и
не очищается, оригинал остаётся. Перезапуск не повторяет сетевую операцию.

## HTTP, Tailscale и собственные серверы

Укажите base URL и нажмите «Сохранить». Для нового HTTP-адреса появится отдельное
предупреждение; «Разрешить для этого адреса» подтверждает его и продолжает сохранение.
Отмена оставляет подключение несохранённым. Ранее подтверждённый адрес повторно не
спрашивается; изменение адреса, порта или пути API требует нового согласия.
Разрешений может быть несколько — отдельно для каждого подключения, без списка
заранее зашитых серверов. Существующее разрешение loopback сохраняет совместимость.

В списках провайдеров и выбора моделей стоит **⚠ HTTP**, а в редакторе первая
заметная строка над endpoint сообщает «HTTP — соединение без TLS». Такие же метки
есть на страницах каталога и активных моделей этого подключения.

HTTP сам не шифрует сообщения, файлы, API key и заголовки. Tailscale шифрует
соединения между своими узлами при включённом VPN; llamur не проверяет маршрут и
не обещает, что произвольный HTTP-адрес обслуживается через Tailscale. Разрешайте
доверенные серверы и проверяйте состояние VPN самостоятельно. Подробности:
https://tailscale.com/kb/1504/encryption.

Android network security config допускает cleartext для динамических адресов;
проверка точного подтверждённого base URL выполняется ProviderStore при сохранении
и RemoteNetwork перед каждым открытием HTTP-соединения. Без такого разрешения
запрос не уходит в сеть. HTTPS сохраняет стандартную проверку сертификатов,
редиректы/автоповторы не включаются, HF остаётся строго HTTPS. Изменение transport
permission меняет revision источника, как изменение endpoint; переименование и
обновление ключа при прежних параметрах сохраняют источник. Эта настройка исходящего
клиента не меняет обязательный HTTPS входящего локального API по Wi-Fi.

## Каталог OpenRouter и политика аккаунта

Старый общий JSON-предел32768значений отклонял реальный каталог с38280значениями,
хотя его размер был меньше1МиБ. Для каталога выделен отдельный ограниченный бюджет
8МиБ/262144значения; строгие проверки вложенности/дубликатов/UTF-8 сохраняются.
Кэш содержит только ID, имя и возможности, без длинных описаний. Полный ответ
каталога и ключи в историю не копируются.
Публичный каталог стандартного `https://openrouter.ai/api/v1` загружается без
credentials: отсутствие/истечение API key не мешает выбору модели. Для генерации
сохраняются обычная проверка ключа и правила аккаунта.

Проверка предоставленным временным ключом для
`nvidia/nemotron-3.5-super-vl:free` вернула HTTP404 с причиной
`Free model training violation (account settings)`: endpoint исключён политикой
данных аккаунта. Это отдельная причина отказа, не ошибка model ID. Приложение
показывает объяснение и адрес https://openrouter.ai/settings/privacy; не ослабляет
политику самостоятельно и не подставляет платную модель. Ключ не записывался в
исходники, отчёты или файлы; успешный inference данного аккаунта не заявляется.

## Вложения и файлы ответа

Кнопка «+» у ввода открывает системный выбор файла. Текст UTF-8 доступен локально
и по API. Изображения/PDF предлагаются только если каталог объявляет поддержку
либо пользователь явно отметил её при активации model ID. Имена моделей не
используются для угадывания возможностей. Локальный runtime сейчас текстовый:
текстовый файл включается в prompt, изображения в GGUF не передаются.

- Текст UTF-8: до256КиБ. PNG/JPEG/WebP/GIF/PDF: до3МиБ на файл.
- Не больше4вложений; вместе до6МиБ сериализованного содержимого.
- Полный запрос до8МиБ; живой диалог до12МиБ (и общего RAM-бюджета процесса),
  сохранённая база до256МиБ/1000диалогов. История не обрезается для обхода лимита.
- Байты файлов не сжимаются и не изменяются. Неподдержанный/слишком большой файл
  отклоняется с объяснением. Черновики вложений живут только в RAM интерфейса.

Форматы запроса: Chat `image_url`/PDF `file`, Responses `input_image`/`input_file`,
Anthropic `image`/`document`. Текстовый файл отправляется как текст, не как
скрытая загрузка в файловое хранилище провайдера. Временные вложения остаются в
RAM; у постоянного чата они зашифрованы вместе с перепиской. Большие зашифрованные
записи читаются частями, чтобы не превышать лимит SQLite CursorWindow.

Совместимый Chat API может вернуть изображения как base64 `images[].image_url`:
они показываются карточками со скачиванием. Блоки кода можно сохранить отдельным
файлом; любое сообщение — текстовым файлом через долгое нажатие. Сохранение идёт
через Android «Создать документ» в выбранное пользователем место, код не
исполняется. Ссылки из ответов автоматически не скачиваются. Сгенерированные
картинки не загружаются обратно как изображение следующего запроса; для визуального
обсуждения их можно сохранить и явно прикрепить. Исходные пользовательские
вложения сохраняются в полной истории следующих запросов.

Инструменты/function calls, серверные file IDs/ссылки от code execution,
отдельные Images/Audio API, аудио/видео и OAuth-подписки пока не реализованы.
Поддержка возможности конкретной моделью/провайдером остаётся обязательной.

## История, ключи и ошибки

Выбранный endpoint получает полную историю только своего диалога, системную
инструкцию и явные параметры. Уже начатый диалог не передаётся другому источнику.
Изменение endpoint/протокола/параметров или дополнительных заголовков требует
нового диалога. Переименование и повторный ввод ключа сохраняют идентичность
источника. История не обрезается скрыто.
Signed thinking Claude, encrypted reasoning Responses и reasoning_details
совместимого Chat сохраняются в RAM временного чата либо в зашифрованном
хранилище выбранного постоянного и возвращаются тому же протоколу при
следующей реплике. После прерывания такого ответа нужен новый диалог, чтобы
не отправить неполное служебное состояние.

Ключи и дополнительные заголовки по умолчанию живут в RAM процесса сервиса.
По выбору пользователя они сохраняются с AES-GCM за отдельным ключом
AndroidKeyStore для каждого подключения. Они не возвращаются в UI, не попадают
в обычные Intent extras и не передаются клиентам локального API. «Забыть» удаляет
прежний ключ и заголовки; удаление подключения удаляет и его Keystore alias.
После потери доступа к Keystore введите ключ заново. Android backup отключён.
Публичные настройки подключения/model IDs остаются на диске.

HTTPS использует стандартную проверку сертификата Android. Redirection отклоняется,
автоповторов и замены модели нет. HTTP разрешается к произвольному адресу после отдельного предупреждения и
согласия для этого подключения. Нет TLS-bypass и отправки credential
на адрес из Location. Из ошибки показывается только ограниченное JSON-поле
message с удалением известных credentials; произвольный HTML/сырые тела не
показываются. Корректный частичный ответ сохраняется при сетевой ошибке/Stop;
повреждённый UTF-8 не заменяется молча.

Фоновый запрос использует dataSync foreground service и ограниченный wake lock.
При разрешённых уведомлениях «Ответ готов» открывает нужный живой диалог.
Android/OEM может ограничить сеть или остановить процесс; временная переписка
исчезает, постоянная остаётся зашифрованной. Запрос сам не повторяется.
Уведомления включаются в настройках.

Аккаунт ChatGPT/Claude сам по себе не заменяет API key/billing
соответствующего провайдера. Удалённый сервер имеет собственную политику хранения;
временная переписка только в RAM llamur не означает отсутствие хранения на сервере.
Для native OpenAI отправляется `store:false`, но это не обещание zero retention.

Исторические проверки0.2/0.3 использовали публичный HTTP/SSE fixture, три протокола,
двухходовую историю, auth, JSON fallback, Stop, ошибки, запрет редиректа, UTF-8,
реальный UI и фоновое уведомление. Пройдены на физическом Motorola и16KiB
эмуляторе в указанной области. В0.4 отдельно проверены живой публичный каталог
OpenRouter на Android, большие JSON/SSE, ошибки без утечки ключа, бинарные вложения,
зашифрованное повторное открытие, отправка/получение файлов через сервис и реальное
сохранение через DocumentsUI. Область и APK-хэши — в `docs/progress.md`.
Платная генерация и успешный inference конкретного облачного аккаунта не проверены.
