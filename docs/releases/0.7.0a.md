# llamur 0.7.0a — engine upgrade nightly

Download **llamur-0.7.0a-arm64-v8a.apk** from the
[release assets](https://github.com/gordeev/llamur/releases/tag/v0.7.0a).
Requires **Android 9+ and an ARM64 OS**. VersionCode is **16**. This is an
experimental nightly with incomplete engine/model qualification.

## Installation and signing change

**The original 0.6.x release key was lost. This APK uses a new nightly key and
cannot update 0.6.x in place.** Save anything needed before uninstalling the old
app and installing this APK. Uninstalling deletes local chats, settings, saved
credentials and app-private model copies. Model files in shared Downloads remain.
There is no automatic data migration between the signing identities.

Nightly signing certificate SHA-256:

```text
8602fac88661f7eb7be62d0e3ceb91c5ef9250eec00af0e471b420f2eedf260f
```

The About screen explains the nightly signature. Use the release's `SHA256SUMS`
and `SIGNING-CERTIFICATE.txt` to check the downloaded APK. See
[signing and verification](../signing.md).

## Changes

- Upgrade the embedded engine to **llama.cpp v0.9.0**, pinned to
  `cd959bae99ff4bed22bef2604f45241c09bbb8c8`, with the locked local runtime patch.
  Historical B0 and earlier experimental variants keep their original source pin.
- Preserve original GGUF weights, quantization and F16 KV. Models remain separate
  downloads; this update does not distribute or rewrite their weights.
- Use current CPU `no_alloc` context/compute plans for unknown models and the
  upgraded engine's memory admission. Missing plans or unsupported geometry are
  refused rather than borrowing the old engine's model-specific estimates.
  The estimate includes weights, metadata and CPU workspace reserves; it cannot
  guarantee that Android will never kill the process under memory pressure.
- Disable prefix caching and transient prefill packing for the upgraded engine
  pending requalification. Their UI controls are disabled, and admission/native
  checks reject unsupported use. Historical optimization results remain historical.
- Retain English/Russian UI and disclose the nightly signing identity in About.

## Verification and limits

Strict dependency verification remained enabled for debug, instrumentation and
unsigned release builds. Full Android lint completed with **zero errors and
49 warnings**. **81 Python bench tests**, **6 source-lock tests** and fresh JVM CPU
admission checks passed. Admission checks covered current LFM3 allocation plans at
4K/32K, exact budget refusal, and unsupported configurations.

The actual signed release APK passed packaging checks: ARM64 only, ELF 16 KiB
and ZIP alignment, a non-debuggable manifest, expected permissions, matching
packaged notices, and no bundled models, credentials or unwanted GPU backends.
Its 14 native libraries have no DWARF debug sections. The signed APK was cleanly
installed on a physical Motorola Edge 40 Pro. These are build, packaging and
installation checks; they do not certify model quality. **No Linux build
reproducibility result is claimed for this nightly.**

**Cross-engine numerical diagnostic gates failed.** This release does not claim
numerical equivalence to the earlier engine or a completed model-quality
qualification.

Separately, LFM3 passed the current engine's standalone host/phone comparison:
**57 teacher-forced tokens** across code and Russian fixtures had matching prompt
and teacher token IDs, finite results, **zero NLL difference**, matching top-eight
sets and **zero top-eight value difference**. Phone arithmetic with thinking off
and on completed at EOG in 9 and 70 tokens; the multi-turn identifier check passed
at EOG in 12 tokens. These are small, fixed controls. They do not establish general
model quality. The actual Android-service CPU planning, admission, GGUF loading
and completed LFM3 chat reply also passed. Tiny-model app regressions passed for
repeated Stop/recovery, overflow, the 1536-token output budget, notification Stop,
process death/reload and preservation of the loaded model after planner refusal.
Large-model cancellation and screen-off release notification checks were not
repeated for this nightly.

A preliminary Gemma screening on Motorola Edge 40 Pro used 7 threads, 8K context,
batch 512 / micro-batch 128, and two measured runs per engine in ABBA order. Prefill increased from about
**12.6075 to 19.9409 tokens/s (+58%)**; decode changed from **5.8475 to
5.7735 tokens/s**. This small screening is not a sustained-performance or quality
acceptance result. Ornith measurements were confounded by swap; **no accepted
Ornith performance gain is claimed**. Earlier published packing gains and
long-context controls used the old engine and do not qualify this upgrade.

and about 6% lower decode; no LFM3 speedup is claimed. These short measurements
do not establish sustained or in-app throughput.

## Русский

Nightly **0.7.0a** обновляет движок до llama.cpp v0.9.0 и использует актуальные
CPU-планы выделения памяти при допуске модели. Исходные веса, квантизация и F16 KV
сохраняются. Кеш префикса и временная упаковка prefill отключены до повторной
проверки нового движка.

**Исходный release-ключ 0.6.x утерян. Подпись новая, обновление поверх 0.6.x
невозможно.** Перед удалением старого приложения сохраните всё нужное: будут
удалены локальные чаты, настройки, учётные данные и модели во внутреннем
хранилище приложения. Модели в общей папке Downloads останутся. Новый SHA-256
сертификата указан выше; канал nightly также отмечен в экране «О приложении».

Сборки со строгой проверкой зависимостей, lint и автоматические проверки допусков
прошли. Между старым и новым движками численные диагностические пороги **не
пройдены**; завершённая проверка качества моделей не заявляется. Отдельное
сопоставление LFM3 с текущим движком на host и телефоне прошло: 57 токенов
teacher forcing совпали по NLL и top-8 без отклонений, проверки арифметики
с thinking и без него и многоходового диалога завершились на EOG. Это небольшие
фиксированные проверки. Через Android-сервис приложения также прошли расчёт
памяти, допуск загрузки, загрузка GGUF и завершённый ответ LFM3.
Предварительный рост prefill Gemma на 58% получен лишь на
двух замерах каждого движка в порядке ABBA и не подтверждает устойчивую скорость или качество. Замеры
Ornith смешаны с влиянием swap, принятый выигрыш не заявляется. Воспроизводимость
этой сборки на Linux не заявляется.
